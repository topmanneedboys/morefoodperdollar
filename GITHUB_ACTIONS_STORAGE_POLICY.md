# GitHub Actions storage policy

Audit date: 2026-09-16 (UTC)

## Baseline and cleanup

The repository Actions API reported 2,039 artifacts totaling 50,170,621,333
bytes (about 50.2 GB decimal). 1,201 were active (36,406,406,192 bytes) and
838 were expired (13,764,215,141 bytes). The largest groups were repeated
`ValuePilot-v101-release` bundles (872 active, about 25.8 GB) and repeated
`ValuePilot-v101-provenance-proof` bundles (318 active, about 10.6 GB).
Intermediate Android parts, browser parts, old debug APKs, and small reports
made up the remainder. No upload step included a Rust `target` directory.

The repository also reported 12 rebuildable Actions caches totaling
569,022,915 bytes (about 543 MiB): Gradle caches and branch-local npm caches.

There were no running workflows during cleanup. The following immutable
artifacts were retained:

- release `10000260926` and provenance proof `10000282677` for the latest
  promoted consumer SHA recorded in `CURRENT_STATE.md` (`3ed5f710…`);
- release `10085397259` and provenance proof `10085413603` for the current
  local engineering checkpoint (`9b11d2b…`);
- the current `github-pages` artifact `10411960143`.

All other 2,034 artifacts were disposable, expired, intermediate, or duplicate
rebuild outputs and were deleted through the repository Actions API. This
removed 50,016,884,759 bytes. The browser-parts artifact left by the failed
pre-fix candidate run (`10429337869`, 59,291 bytes) was then deleted as
disposable. Total cleanup removed 50,016,944,050 bytes. All 12 caches were also deleted; cache contents
are never release or provenance evidence and are regenerated by CI when
enabled. The API's cache-usage aggregate may lag the zero-entry cache listing
briefly after deletion.

After the successful M12.0 candidate run, the repository contains eight live
artifacts totaling 230,725,538 bytes: the five preserved historical/current
evidence artifacts above, the current `github-pages` artifact, and the three
short-lived candidate hand-off/release artifacts from run `35053280023`
(`10430210141`, `10430295317`, `10430340149`). The cache listing is empty
(`total_count=0`). The candidate release expires after three days and its
browser/Android parts after one day; they are rebuildable and are not release
provenance.

Historical release/provenance facts remain in the committed checkpoint and
qualification documents, including code SHAs, artifact digests, and checksum
claims. A historical binary is reproducible from its immutable commit; it is
not retained indefinitely in Actions storage.

## Free-first workflow rules

- Browser and Android hand-off artifacts remain one-day artifacts because they
  are consumed only by the same workflow's release-bundle job.
- Candidate/work-branch release bundles upload only for push events and expire
  after three days. A stale candidate can be rebuilt from its immutable commit
  before promotion.
- The milestone provenance proof remains a 90-day artifact because it is the
  durable binary/checksum evidence for a promoted milestone.
- The Android build workflow does not read or write Gradle or npm Actions
  caches. Removing those caches trades some build speed for predictable free
  storage; outputs are rebuilt when needed.
- Release uploads contain only the explicitly verified browser archives, APK,
  commit marker, and checksum manifest. Generated build trees, Rust `target`,
  national provider data, and raw source archives are never uploaded.

This policy is storage housekeeping only. It does not change ValuePilot's
release gates, provenance semantics, Android offline boundary, or data rights.
